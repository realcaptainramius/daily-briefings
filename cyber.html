Nov 17Uber notifies 149,346 people, mostly drivers, that license data was stolen in the Fireworks AI vendor breach

Uber is notifying 149,346 people, according to a filing with Oregon’s attorney general, that names, addresses, birth dates and driver’s license numbers were stolen from data it had shared with a service provider; TechCrunch and BleepingComputer tie the provider to Fireworks AI (see below), and ID Tech says Uber’s filings name Fireworks. Uber says it learned of the incident on Oct 9 and that the attackers used compromised provider credentials on Oct 7; TechCrunch dates the provider’s own incident to Oct 24, so the timelines in coverage do not fully line up. Notices were filed in at least nine states. No rider payment data is reported to be involved. Seen via search summaries only.

Nov 16–17Optimizely supply-chain attack serves skimmer and wallet-swapping code on about 178 organizations’ websites

Attackers planted malicious JavaScript in the customer-editable Project JavaScript of Optimizely Web projects, and Optimizely’s CDN served it to visitors of sites run by about 178 organizations, including CNN, the BBC, Fox News, Zoom and Salesforce. Report URI’s Scott Helme found the code in 188 of 1,611 snippets checked, says it was not CDN cache poisoning, and reports every file clean by 23:11 UTC on Nov 16. Reported payloads swapped cryptocurrency wallet addresses, skimmed payment cards, collected cookies and screenshots and pushed some iPhone visitors toward exploit code. Optimizely confirmed the attack on Nov 17 and blamed a flaw in its Experimentation account signup flow, but has not explained how that gave write access to unrelated customer projects or how many projects were changed. Losses are unclear: earlier reports put attacker wallet receipts at about $6,600–7,000, while blockchain firm Bitquery counts 19 payments worth about $2,260. The affected sites’ own servers were reportedly not breached. Seen via search summaries only.

Vulnerabilities & Exploits

Nov 17CISA adds exploited Puppet Enterprise deserialization flaw to KEV

CISA added a Perforce Puppet Enterprise deserialization flaw (CVE-2026-115731, CVSS 9.4 in most sources) to its Known Exploited Vulnerabilities catalog on Nov 17, with a Dec 1 federal deadline. Reports say a client holding a certificate signed by the Puppet CA can send a crafted report via HTTP PUT and run code as the Puppet Server service account. Fixes are in Puppet Enterprise 2023.8.13, 2025.12.1 and 2026.0.1; the community fork OpenVox is also affected and a public proof-of-concept targets it, and Vox Pupuli says open-source Puppet has no fix. Accounts of when exploitation began differ (SecurityWeek cites Nov 4, while Perforce’s initial notice reportedly said none was known), and no attacker has been named. A companion authorization bypass (CVE-2026-115732) fixed in the same releases is not in KEV. Seen via search summaries; the CISA page could not be opened.

Nov 17“Java4Shell” OpenJDK Base64 decoder flaw may allow unauthenticated code execution in Java apps

Security firm Calif disclosed on Nov 17 a memory-corruption bug (CVE-2026-114938) in OpenJDK’s hand-written x86-64 Base64 decoder path that uses AVX-512 VBMI instructions, which it says can let unauthenticated attackers take over Java applications that decode attacker-supplied Base64; coverage names apps such as Jira and Jenkins as at risk. Oracle rates it 8.1 (CVSS 3.1) and the researchers 9.2 (CVSS 4.0). It is reported to affect OpenJDK 17.0.6 and later, including 21 and 25, only on CPUs with AVX-512 VBMI. Oracle’s November Critical Patch Update reportedly includes a fix, but sources disagree on upstream status and some Linux distributions had not shipped fixes as of Nov 18. No in-the-wild exploitation is reported. Seen via search summaries of vendor and researcher posts.

Threat Actor & APT Activity

Nov 16–17Google says attackers built an AI agent framework that turns patches into exploits, and a China-nexus group is building its own

Google’s Threat Intelligence Group, with Mandiant, said in a Nov 16 AI Threat Tracker report that it found a multi-agent framework, “exploit_agent,” on an exposed attacker staging server. It compares code before and after a patch, finds the fixed flaw, drafts an exploit and runs it, which GTIG calls the first case it has observed of threat actors fully automating vulnerability research and exploitation with no human in the loop. Google notes the agents also hallucinate details and nonexistent targets, and BleepingComputer reports Google expects largely hands-off attacks by unsophisticated actors within about three months. The same report, highlighted by The Record on Nov 17, says a PRC-nexus group is developing its own automated attack framework for likely espionage use, and that ARTEX (see below) is mainly used by Chinese-speaking groups; Google’s wording does not name a specific state agency. VentureBeat says the report names no exploited flaw or victim count. Seen via search summaries only.

Nov 17Microsoft’s agent-framework PyPI package poisoned with stealer targeting Azure, Azure DevOps and GitHub Actions secrets

Two malicious releases of Microsoft’s official agent-framework Python package, 1.26.1 (uploaded at 20:35 UTC on Nov 17, per Wiz) and 1.26.2 about 33 minutes later, carried a credential stealer that ran via a .pth startup file on every Python launch, even if the package was never imported. Researchers say it harvested credential environment variables, Azure CLI data, Git credential stores, Docker and npm configs and .env files, and requested cloud and CI workflow identity tokens. Both versions were quarantined on PyPI; 1.26.0 is the last clean release, and anyone who installed either bad version is advised to rotate all secrets on that machine. How the attacker got publishing access is unknown, and OpenSourceMalware suggests it may have persisted after the first takedown; Microsoft has reportedly acknowledged the incident. Seen via search summaries of researcher posts.
